# 0005：工程任务使用 Hermes 原生容器工具

日期：2026-09-20。依据：负责人要求最大化复用原生 Hermes harness，保留 Mikasa 身份、记忆、skills 与工程门禁。

## 所有权

Hermes 官方 AIAgent 负责推理、上下文压缩、原生文件/搜索/终端、SOUL、任务记忆、skills 与工具调度。CCH 负责模型路由与两种模型协议的服务供应。Mikasa 不实现另一套模型循环，只适配结构化交付，并持有仓库授权、任务事实、工作区快照、完整读取证据、验收命令、提交和独立审批。

聊天使用每账号 Gateway；工程使用每任务 profile 的官方 SDK。两者有不同生命周期和权限范围，不强行共用一个 AIAgent 对象，也不把工程仓库数据写入普通账号记忆。工程 SessionDB 由 Hermes 写入，每次调用创建原生 session；跨修复调用的任务事实与检查结果仍由 Mikasa 提供。

## 工作区边界

实现从暂存树导出，审查和拆解从固定 head 导出；仅普通 UTF-8 文件进入快照。凭据、Git 元数据、执行配置、符号链接、二进制与超限文件排除并报告。原生 Docker 只获得快照及受信任 skills 的挂载，不获得真实仓库、profile、控制面 token 或模型密钥。网络关闭、根文件系统只读、限制资源；计划/审查挂载只读。

原生 shell 可以运行容器中的命令。独立验收仍使用无自定义命令参数的 `mikasa_run_checks`：宿主暂停本任务容器，检查并导入差异，再运行配置中的检查。最终先清理容器，导入剩余差异、重新验证、创建本地提交，停在等待独立审查。取消、超时和失败也回收该任务容器。

读取证据来自官方 post_tool_call 的真实 read_file 输出，经专用 FD 到宿主；逐行核对固定快照并累计覆盖。读取尾页、搜索命中、终端输出或模型自报不能冒充完整阅读。规则修改和审批仍使用基线，不能让待审内容授权自身。

## 兼容与限制

内置 Hermes 路径没有旧工具开关，不使用 Mikasa 自研 list/read/search/apply。可配置第三方 worker 的公开 version=1 RPC 仍按原合同工作；升级到下一版协议时连同调用方和协议测试删除该兼容层。

默认工程镜像固定为 Python 3.12 slim digest；其他语言需要运维在 `agent_image` 中配置预装依赖的镜像。最终验收使用单独的 `check_image`。不支持在快照中交付二进制、链接、文件权限变更或超限文件；不能把合成 Python 验收当成任意仓库就绪。

原生模型调用失败诊断只保留固定错误码、异常类型与栈位置。敏感 profile 和原始报告不进入 Git。外部 GitHub/飞书配置、VM 和 FluxCore 实仓验收仍按既定顺序推进，当前未执行发布或部署。
