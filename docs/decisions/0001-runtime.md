## 背景和范围

负责人明确：FluxCore 只用于测试 Mikasa 是否正常运行，先完成 Mikasa 本体开发。因此开发和验证使用临时 Git 仓库、模拟 GitHub 和进程级模型夹具；不修改 FluxCore、不配置真实仓库保护、不发送外部消息。

本轮覆盖已确认 MVP：审计、拆解、派发或执行、PR 审查、进度跟进。飞书权限接入安排在 VM 部署前；Codex/Claude 执行器仍是可选项，工程 skills 已有本地适配，不伪造部署状态。

## 选择

- Python 3.12+ 标准库承担控制面，底层直接采用固定官方 Hermes harness 的 `AIAgent.run_conversation`、上下文管理和工具调度；插件经官方 `PluginContext.register_tool` 注册。扩展取舍以协作开发、质量监督和交付推进为依据，优先官方扩展点，不自研平行推理循环。核心本地测试不依赖外部服务和 API key。
- SQLite 是任务与事件的唯一事实源；workspace、worker、tool、validation、commit 阶段实时写入现有事件表，按当前运行令牌校验所有权，失败后仍可追查；GitHub 提供仓库、PR、CI、正式审批事实。文本记忆不覆盖当前版本证据。
- 独立进程运行 Hermes，通过官方插件工具和专用 FD 通道主动探索仓库、应用修改、运行配置检查并修复失败。控制面按任务授予只读或实现工具，校验路径、检查完整性与调用证据；不开放任意 shell 或发布工具。详见 [工具覆盖验证](../HERMES_TOOLS_VALIDATION.md)。
- 本地 CLI 信任操作系统账号；HTTP 使用每个成员独立环境 token 映射身份。仅负责人派发、启动实现、发布和确认归属；成员可查询和提交分析需求。
- 文件实现使用独立 clone，不触碰输入仓库；生产验证命令放入只挂载该工作区、禁用网络和特权的容器，`.git` 单独只读挂载。仅测试夹具显式允许本机验证。
- `queued → running → done / awaiting_review / blocked / failed`；取消进入 `cancelled`，显式重试回到 `queued`。依赖任务必须真正 `done` 才能开始。
- 模型或验证失败最多修复配置的轮数，默认 3；不会无限重试。暂停终止模型或检查子进程并保留任务现场；恢复运行不自动重试失败任务。
- 实现通过检查后只达到 `awaiting_review`。对其发布草稿 PR 后，由负责人独立批准、有权限的人手动合并，再由 `reconcile` 核对产出、审批、CI 和合并事实标记完成。
- 发布以任务为单位持久化 `pending/sent/uncertain`。发生网络歧义不自动重发；保留回执和人工核对入口，避免重复 Issue、PR 和 Review。

## 审批完整性

人类归属绑定当前 head；未知归属不能批准。PR 一旦记录 Mikasa 参与实现，后续提交和账号变化不会清除该归属。Mikasa 创建的 PR 自动按自作产出处理。审查同时绑定目标基线；发布前再次检查 head、基线和 CI。平台门禁是否强制执行，取决于尚未部署的 GitHub 分支保护或受控检查。

## 取舍和限制

当前为单 VM、单 runner 架构，使用 POSIX 进程组和文件锁，不支持原生 Windows 或多机分布式调度。代码与检查镜像需要在目标 VM 预先安装，容器验证不在运行中下载依赖。模型上下文有大小上限，遗漏文件会明确记录；可通过固定 head 的完整工具读取补齐，仍未读取的变更文件阻止批准；模型推理质量仍需真实联调证明。

不选外部看板可减少初始接入和双事实源冲突。未来需要多机工作器时，先迁移事务、租约和任务事实源，不在 SQLite 文件上叠加网络共享。扩展工具执行前须保持凭据隔离、独立审批和当前版本验证。

## 重新评估和恢复

运行时状态可以通过 SQLite backup API 备份。停止服务后恢复数据库和对应工作区；中断任务将进入失败状态等待检查，已发布操作不得无条件重发。若替换存储、Hermes 接口或执行器，保留 task ID、事件、归属和发布回执，先以当前隔离测试验证兼容性。
